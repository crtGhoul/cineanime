I cloned and audited crtGhoul/cineanime across the web PWA (index.html, sw.js, servers.json), native wrappers (android-tv/, windows-desktop/), sync relay (sync-worker/), and live endpoints.

CineAnime already has a strong zero-backend foundation (static relative paths, Kitsu → AniList catalog failover, encrypted vaults, Stremio addon protocol, and a remote servers.json registry). However, several live infrastructure issues, server-routing bugs, and player defaults currently hurt both 1080p playback and long-term survivability.

1. Ensuring Videos Play in ≥1080p

CineAnime plays video in two ways: Third-Party Embed Iframes (Servers 1–4) and the Direct HTML5 / hls.js Player (Stremio addons). Right now, both paths leave 1080p on the table:

A. Fix the Broken SERVERS Routing & Duplicate Buttons (index.html:4690–4708, 5649–5685)

There is a major mismatch between what the UI server buttons say and what SERVERS actually loads:

  • Only 2 providers are actually wired for Movies/TV: server1 and server4 both return the exact same buildCineSrcUrl(...), while server2 and server3 both return buildVidZeeUrl(...).
  • buildSmashyUrl is dead code (and its domain is blocked): buildSmashyUrl (index.html:5610) is never called in SERVERS, and https://embed.smashystream.com in servers.json currently returns HTTP 451 (Unavailable For Legal Reasons).
  • Anime gets hijacked away from ZokoAnime (breaking 1080p SUB/DUB & multi-season anime): In SERVERS.server1–server4 (index.html:5653), any item with an imdbId or tmdbId is routed to CineSrc or VidZee instead of ZokoAnime—even though the Anime UI buttons say ZokoAnime HD and Zoko HardSub! Because ANIME_CATALOG includes tmdbId and selectAnime() asynchronously populates anime.imdbId (index.html:6375), clicking SUB/DUB or Server 2 (Zoko HardSub) on popular anime silently loads CineSrc/VidZee with ?s=1&e=<ep>, which also breaks absolute-numbered anime (One Piece, Bleach, Attack on Titan).

How to fix for reliable 1080p:

  1. Route Anime server1 (sub/dub) and server2 (hsub) unconditionally to ZokoAnime (when idMal/aniId is present), and keep server3 (CineSrc) + server4 (VidZee or a new anime embed mirror) as distinct fallbacks.
  2. Replace dead smashystream in servers.json so all 4 Movie/TV buttons hit 4 distinct 1080p multi-CDN aggregators rather than 2 duplicated URLs.

B. Tune hls.js to Lock Onto ≥1080p Immediately (index.html:7455–7473)

Currently, hls.js is initialized with minimal defaults:

activeHlsInstance = new Hls({ enableWorker: true, lowLatencyMode: false });

By default, hls.js starts with a low bandwidth estimate (~500 kbps), causing streams to open in 360p/480p/720p before ramping up, and can cap resolution on high-DPR mobile/TV WebViews if player CSS dimensions are smaller than 1920×1080.

How to guarantee ≥1080p when available:

  • Set capLevelToPlayerSize: false and raise abrEwmaDefaultEstimate: 8_000_000 (8 Mbps) so hls.js immediately qualifies 1080p segments from frame 1.
  • In Hls.Events.MANIFEST_PARSED, sort data.levels descending (2160p, 1080p, 720p) with bitrate labels, and set activeHlsInstance.startLevel (or minAutoBitrate) to the best ≥1080p level by default—falling back to lower resolutions only if a buffer stall (BUFFER_STALLED_ERROR) occurs or if the stream's max resolution is 720p.
  • Persist the user's preferred quality target (Auto 1080p+, 2160p, 1080p, Data Saver) in cineanime_prefs.

C. Upgrade Stremio Addon Stream Ranking, Codecs & Anime IDs (index.html:9430–9646)

Direct Stremio streams (via Debrid or HTTP addons) are the single best way to guarantee true high-bitrate 1080p / 4K long-term because CineAnime controls the <video> element directly:

  1. Smart 1080p + Browser-Safe Codec Sorting: Currently refreshTheaterAddonStreams renders streams in raw addon order (index.html:9622), and extractStreamQuality (index.html:9454) only checks 2160p|4k|1080p|720p|480p. Many 4K/1080p .mkv torrents use EAC3/DTS/TrueHD audio or HEVC profiles that trigger the browser codec failure banner (#streamCodecBanner). Scoring streams by Cached Direct HTTPS → 1080p/2160p → MP4/HLS/H.264/AAC over MKV/DTS puts playable 1080p streams first.
  2. Support kitsu:<id>:<ep> for Anime Addons: resolveImdbIdForAddonLookup (index.html:9430) only looks up IMDb tt... IDs via Cinemeta title search. Anime Stremio addons (Torrentio, Comet, MediaFusion, AnimeTosho) index seasonal anime primarily by kitsu:<kitsuId>:<ep>. Querying both kitsu: and tt: unlocks 1080p SubsPlease / Blu-ray streams for anime that lack clean IMDb season mappings.
  3. "Auto-Play Best ≥1080p Direct Stream" Toggle: Currently updatePlayerUrl() always loads iframe embeds first, forcing users to scroll down and manually click a direct addon stream on every episode. Adding an auto-play preference lets Theater launch the best ≥1080p direct stream automatically and fall back to iframe embeds only if none exist.
